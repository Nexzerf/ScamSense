# ป้องกันสายโทร + ผู้ช่วย AI รับสายแทน

## ภาพรวม

```
 สายเข้า ─► มือถือผู้สูงอายุ
              │  เบอร์อยู่ในรายชื่อผู้ติดต่อ? ──► ดังตามปกติ (ScamSense ไม่แตะ)
              ▼  ไม่อยู่ในรายชื่อ → ScamCallScreeningService (เฟส 1, ในเครื่อง)
      ┌───────┴─────────────────────────────────────────────┐
      │ +697/+698, เบอร์ที่รายงานไว้, (ต่างประเทศ ถ้าเปิด) → บล็อก + แจ้งเตือน │
      │ ไม่ได้จับคู่ผู้ช่วย → ดังได้ + แจ้งเตือนวิธีสังเกตมิจฉาชีพ             │
      │ จับคู่ผู้ช่วยแล้ว → ปฏิเสธสาย → ซิมโอนสาย (เมื่อไม่ว่าง) ไปเบอร์ผู้ช่วย  │
      └───────┬─────────────────────────────────────────────┘
              ▼ (เฟส 2, เซิร์ฟเวอร์ของคุณ)
      ผู้ช่วย AI รับสาย: "สวัสดีค่ะ ที่นี่ผู้ช่วยรับสายอัตโนมัติ… กรุณาแจ้งชื่อและธุระ"
      เสียง → ข้อความ (speech recognition ของผู้ให้บริการโทรศัพท์) → ScamAnalyzer (ตัวเดียวกับในแอป)
        ├─ อันตราย  → "เจ้าของเบอร์ไม่สะดวกรับสาย" + วางสาย + SMS เตือนผู้สูงอายุและลูกหลาน
        ├─ ปลอดภัย  → กระซิบสรุปให้ผู้สูงอายุฟัง แล้วโอนสายเข้า (มาจากเบอร์ผู้ช่วย ซึ่งแอปปล่อยผ่าน)
        └─ ไม่ชัดเจน → ถามเพิ่ม (สูงสุด MAX_TURNS) แล้วรับฝากข้อความ + SMS
      แอปดูประวัติ + ข้อความที่ถอดจากสายได้ที่ "สายที่ผู้ช่วยรับแทน"
```

## ทำไมออกแบบแบบนี้
- Android ไม่อนุญาตให้แอปทั่วไปฟังเสียงในสาย (`CAPTURE_AUDIO_OUTPUT` สงวนไว้ให้แอประบบ, Google Play ห้ามใช้ Accessibility อัดเสียงสาย) จึงใช้ **การโอนสายของเครือข่าย** ให้เสียงไปถึงผู้ช่วยแทน (แนวทางเดียวกับบริการผู้ช่วยรับสายเชิงพาณิชย์)
- Android ส่งเฉพาะเบอร์ที่ **ไม่อยู่ในรายชื่อผู้ติดต่อ** ให้ `CallScreeningService` (เมื่อไม่ขอ READ_CONTACTS) — สายจากครอบครัวจึงไม่ถูกแตะ
- ป้องกันการวนลูป: สายที่ผู้ช่วยโอนกลับมาใช้เบอร์ผู้ช่วยเป็น caller ID → แอปปล่อยผ่าน; ถ้าเครื่องไม่ว่างและสายเด้งกลับ เซิร์ฟเวอร์ตอบ `<Reject>`

## ข้อจำกัดที่ควรรู้
- ตรวจได้ **ก่อนรับสาย** เท่านั้น สายที่ผู้สูงอายุรับเองแล้วระบบไม่ได้ยิน
- ฟีเจอร์กรองสายต้องใช้ **Android 10+** (บล็อกเบอร์ได้ตั้งแต่ Android 10; Android 6–9 ใช้การตรวจเบอร์ด้วยตนเองได้)
- ต้องมี **เบอร์โทรไทย** จากผู้ให้บริการที่รองรับ TwiML (เช่น Twilio) — การโอนสายไปเบอร์ต่างประเทศมีค่าใช้จ่ายสูงกับผู้ใช้
- **ภาษาไทยของ speech recognition**: Twilio ส่งต่อไปยัง Google/Deepgram ซึ่งรองรับภาษาไทย แต่ต้องทดสอบชุด `STT_LANGUAGE` / `SPEECH_MODEL` / `TTS_VOICE` กับบัญชีจริง (ตั้งค่าได้โดยไม่ต้องแก้โค้ด)
- ค่าใช้จ่าย: ค่าเบอร์รายเดือน + ค่าสายเข้ารายนาที + ค่า speech recognition + SMS (และค่าโอนสายของซิมผู้ใช้ ตามโปรโมชันเครือข่าย)

## ติดตั้งเซิร์ฟเวอร์

```bash
./gradlew :server:test :server:fatJar
docker build -t scamsense-assistant server/
docker run -d --name scamsense -p 8080:8080 --env-file server/.env -v scamsense-data:/data scamsense-assistant
```
วางไว้หลัง HTTPS reverse proxy (Caddy/Nginx/Cloud Run ฯลฯ) ให้ `PUBLIC_BASE_URL` ตรงกับ URL สาธารณะทุกตัวอักษร (ใช้ตรวจลายเซ็น Twilio)

ตั้งค่าเบอร์ใน Twilio: Voice webhook (A call comes in) → `POST https://<PUBLIC_BASE_URL>/voice/incoming`

| ตัวแปร | จำเป็น | ความหมาย |
|---|---|---|
| `PUBLIC_BASE_URL` | ✔ | URL HTTPS สาธารณะ |
| `TWILIO_AUTH_TOKEN` | ✔ | ใช้ตรวจลายเซ็น webhook (ไม่มี = ปฏิเสธทุก webhook) |
| `TWILIO_ACCOUNT_SID` | สำหรับ SMS | ส่ง SMS เตือน |
| `ADMIN_TOKEN` | ✔ (≥24 ตัว) | เปิด admin API |
| `STT_LANGUAGE`, `SPEECH_MODEL`, `TTS_VOICE` | – | ภาษา/โมเดลเสียง (ค่าเริ่มต้น th-TH) |
| `RETENTION_DAYS` | – | ลบบันทึกสายอัตโนมัติ (ค่าเริ่มต้น 30 วัน) |
| `MAX_TURNS` | – | จำนวนคำถามสูงสุด (2–5) |

## เพิ่มผู้ใช้ และจับคู่แอป

```bash
curl -X POST https://<host>/admin/subscribers \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"สมศรี","phone":"081-234-5678","caregiverPhone":"089-999-9999","assistantNumber":"02-123-4567"}'
# => {"subscriberId":1,"pairingCode":"TV485KKL","expiresAt":...}   (ใช้ได้ครั้งเดียว ภายใน 15 นาที)
# ขอรหัสใหม่:  POST /admin/subscribers/1/pairing-code
```

ในแอป: **ตั้งค่า → ป้องกันสายโทร**
1. เปิดการกรองสาย (อนุญาตบทบาท "Call screening") + อนุญาตการแจ้งเตือน
2. ใส่ที่อยู่เซิร์ฟเวอร์ + รหัสจับคู่
3. กดปุ่ม ก./ข./ค. เพื่อตั้งค่าโอนสายในซิม (`**67*`, `**61*`, `**62*`) แล้วกดโทร → ติ๊ก "ตั้งค่าเรียบร้อยแล้ว"
4. ยกเลิกทั้งหมดได้ด้วยปุ่ม "ยกเลิกการโอนสายทั้งหมด" (`##004#`)

## ความปลอดภัยและ PDPA
- ผู้ช่วยแจ้งผู้โทรทุกครั้งว่าเป็นระบบอัตโนมัติและมีการบันทึก/ถอดความ
- Webhook ทุกตัวตรวจลายเซ็น HMAC ของ Twilio (fail closed); ข้อความที่ผู้โทรพูดถูก XML-escape ก่อนอ่านกลับ (กัน TwiML injection)
- Device token สุ่ม 256 บิต เก็บแบบ SHA-256 บนเซิร์ฟเวอร์, เข้ารหัส Keystore บนมือถือ; รหัสจับคู่ใช้ครั้งเดียว หมดอายุ 15 นาที จำกัด 10 ครั้ง/นาที/IP
- แอปคุยกับเซิร์ฟเวอร์ผ่าน HTTPS เท่านั้น และไม่เชื่อ CA ที่ผู้ใช้ติดตั้งเอง (กันมิจฉาชีพหลอกให้ติดตั้งใบรับรองดักข้อมูล)
- เลขยาว ≥6 หลักในข้อความถอดเสียงถูกปิดบังก่อนบันทึก; ลบอัตโนมัติตาม `RETENTION_DAYS`; ผู้ใช้ลบทั้งหมดได้จากแอป
- ไม่ log ข้อความที่ถอดจากสาย
- ก่อนใช้งานจริงควรปรึกษาที่ปรึกษากฎหมายเรื่อง PDPA และการบันทึกเสียงสนทนา
